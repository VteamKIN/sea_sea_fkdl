## 产品概述

优化智能车图像处理模块的边线跟踪算法，实现完整且连续的边线检测功能。

## 核心功能

- 改进边线存储方式：从一维数组改为结构体列表存储，支持存储完整的L形、直角弯等复杂边线
- 优化跟踪算法：基于现有的左右手自适应跟踪函数，实现方向感知的边线跟踪
- 数据融合：将边线点列表转换为逐行边界数组，保持与后续处理模块的兼容性
- 解决断线和追踪不完整问题，能够准确捕捉直角弯道的完整边线轮廓

## 技术栈

- 基于现有TC2xx平台和C语言
- 保持当前的逆透视变换和自适应阈值策略
- 复用已有的左右手跟踪函数框架

## 技术方案

### 核心问题分析

**当前存储方式的限制**：

```c
int16 left_boundary[WARP_IMAGE_H];   // left_boundary[y] = x
```

- 每行只能存储一个x坐标
- 无法表示水平边线（同一y，多个x点）
- L形边线的水平段无法完整记录

**当前检测算法的问题**：

- `zi_shi_ying_warp()` 采用逐行扫描+从道路中心向两侧搜索
- 直角弯时搜索起点偏离实际边线位置
- 无法跟踪垂直走向的边线段

### 解决方案

#### 1. 新增边线点结构体存储

```c
#define MAX_EDGE_POINTS  200

typedef struct {
    int16 x, y;        // 坐标
    uint8 type;        // 类型：0=正常, 1=垂直段, 2=拐点
} EdgePoint;

EdgePoint left_edge[MAX_EDGE_POINTS];
EdgePoint right_edge[MAX_EDGE_POINTS];
int16 left_edge_count;
int16 right_edge_count;
```

#### 2. 优化左右手跟踪算法

- 调整起始位置搜索策略
- 在逆透视图像上运行跟踪
- 增加拐点检测和标记

#### 3. 数据格式转换

- 将边线点列表按y坐标分组
- 每行取最左/最右的点作为边界
- 保持`left_boundary[]`和`right_boundary[]`数组供后续模块使用

### 架构设计

```
逆透视图像
    │
    ▼
起点检测 ──────┬────── 起点检测
              │
    ┌─────────┴─────────┐
    │                   │
    ▼                   ▼
左手跟踪            右手跟踪
(left_edge)        (right_edge)
    │                   │
    └─────────┬─────────┘
              │
              ▼
    边线点列表（结构体存储）
              │
              ▼
    转换为逐行边界数组
              │
              ▼
    left_boundary[] / right_boundary[]
              │
              ▼
    中线计算 / 道路识别
```
