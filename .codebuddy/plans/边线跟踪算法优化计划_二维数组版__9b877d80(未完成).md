## 产品概述

优化智能车图像处理模块的边线跟踪与道路识别算法，实现完整且连续的边线检测功能。

## 核心功能

- 改进边线存储方式：从一维数组改为二维数组坐标点列表存储，支持存储完整的L形、直角弯等复杂边线
- 优化跟踪算法：基于现有的左右手自适应跟踪函数，实现方向感知的边线跟踪
- 同步优化道路识别函数：detect_corner、detect_road、detect_road_type 适配新的边线数据格式
- 解决断线和追踪不完整问题，能够准确捕捉直角弯道的完整边线轮廓

## 技术栈

- 基于现有TC2xx平台和C语言
- 保持当前的逆透视变换和自适应阈值策略
- 复用已有的左右手跟踪函数框架

## 核心问题分析

### 当前存储方式的限制

```c
int16 left_boundary[WARP_IMAGE_H];   // left_boundary[y] = x
```

- 每行只能存储一个x坐标
- 无法表示水平边线（同一y，多个x点）
- L形边线的水平段无法完整记录

### 当前检测算法的问题

- `zi_shi_ying_warp()` 采用逐行扫描+从道路中心向两侧搜索
- 直角弯时搜索起点偏离实际边线位置
- 无法跟踪垂直走向的边线段

## 解决方案

### 1. 新增边线点二维数组存储

```c
#define MAX_EDGE_POINTS  200

// 左手边线点列表
int16 left_edge[MAX_EDGE_POINTS][2];   // [i][0]=x, [i][1]=y
int16 left_edge_count;                  // 实际点数

// 右手边线点列表
int16 right_edge[MAX_EDGE_POINTS][2];  // [i][0]=x, [i][1]=y
int16 right_edge_count;                 // 实际点数

// 拐点标记（存储拐点在边线数组中的索引）
int16 left_corner_index;   // 左边线拐点位置（-1表示无拐点）
int16 right_corner_index;  // 右边线拐点位置（-1表示无拐点）
```

### 2. 拐点检测策略（速度快、效果好、不冲突）

**方案：跟踪过程标记 + detect_corner() 综合验证**

**实现逻辑**：

1. 在左右手跟踪过程中，当方向发生突变（转90度）时记录拐点索引到 `left_corner_index` / `right_corner_index`
2. detect_corner() 综合利用多种方法：

- 跟踪标记的拐点索引（快速、直接）
- 丢线检测（辅助验证）
- 中线突变检测（补充验证）
- 斜率突变检测（补充验证）

3. 多种方法相互验证，提高准确性

### 3. 道路识别函数优化

**detect_road() 优化**：

- 保持基于像素跳变的检测逻辑
- 可选：利用新的边线信息进行验证（如宽度突变）

**detect_road_type() 优化**：

- 适配新的拐点检测方式
- 考虑跟踪过程中标记的拐点信息

### 4. 数据融合

将左右手跟踪结果转换为逐行的边界数组：

- 将边线点列表按y坐标分组
- 每行取最左/最右的点作为边界
- 保持 `left_boundary[]` 和 `right_boundary[]` 供后续模块使用

## 实现要点

### 性能考虑

- 边线点数限制在200以内
- 使用CPU1数据RAM存储（已配置）
- 避免重复计算局部阈值

### 抗干扰能力

- 保持自适应阈值策略
- turn计数限制为8，允许跟踪直角弯
- 多种拐点检测方法相互验证

### 兼容性

- 保留原有的边界数组供控制模块使用
- 后续处理模块无需修改
